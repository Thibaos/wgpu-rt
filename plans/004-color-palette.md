## Why this matters

All voxels currently render as a single hardcoded brown `(0.6, 0.45, 0.3)`. The
shader's `Tree64RayCast` correctly extracts a per-voxel material ID from the
leaf data (`ReadLeafMaterial_0`), but the entry point discards it — it only
checks `MaterialId != 0` for hit/miss detection and applies a hardcoded color.
There is no palette resource on the GPU at all, no palette binding in the bind
group, and the .world format stores no palette data despite the source .vox file
containing a full 256-color RGBA palette (`dot_vox::DotVoxData::palette`).

After this plan, each voxel renders with its actual MagicaVoxel color (with
the same lambertian diffuse lighting already in place). The palette travels
end-to-end: .vox → bake → .world → GPU buffer → shader.

### dot_vox palette API:

The `dot_vox` crate provides `DotVoxData::palette: Vec<Color>` where `Color` is:

```rust
// dot_vox::palette::Color
pub struct Color { pub r: u8, pub g: u8, pub b: u8, pub a: u8 }
```

Also available: `dot_vox::DEFAULT_PALETTE: &[Color]` (256 entries). The palette is
RGBA8 per entry, up to 256 colors. `Voxel::i` is the 0-based palette index.

```
[TOC: N × 16B]   ← N = 256 for default 16×1×16 grid
[Chunk data blob 0]

...
```

## Steps

### Step 1: Bump .world format version and add palette to WorldFile

`src/formats/mod.rs` — bump `WORLD_VERSION` from 1 to 2, add palette
read/write to `WorldFile`.

**CRITICAL — backward compat**: `WorldHeader::read` currently rejects any
version != WORLD_VERSION (`if header.version != WORLD_VERSION` around line
68). After bumping WORLD_VERSION to 2, v1 files would be rejected. Change
the check to `if header.version > WORLD_VERSION` so both v1 and v2 are
accepted. v1 files then reach the "fill with zeros" fallback below.

Changes to `WorldHeader`: none (palette won't fit in the 32 reserved bytes;
we store it as a separate blob after the TOC).

New .world layout (v2):
```
[Header: 64B]        ← version = 2
[TOC: N × 16B]
[Palette: 1024B]     ← 256 colors × 4B RGBA8 (always exactly 1024 bytes)
[Chunk data blob 0]
[Chunk data blob 1]
...
```

The palette is always exactly 1024 bytes. If no palette is available, fill
with zeros (then the shader falls back or renders black). Pad/truncate to
exactly 256 entries.

Add `pub palette: [[u8; 4]; 256]` field to `WorldFile`.

In `WorldFile::write`:
- After the TOC zero reservation (after `writer.write_all(&zeros)?`), write
  1024 bytes of palette data by flattening `self.palette` into a `[u8; 1024]`
  and calling `writer.write_all(&palette_bytes)?`.
- The chunk offsets (computed dynamically at `writer.stream_position()`) will
  naturally shift past the palette — no TOC math changes needed.

In `WorldFile::read`:
- After reading the TOC, if version >= 2, read 1024 bytes into a
  `[[u8; 4]; 256]`.
- For version 1, fill with zeros and log a warning: "World file version 1 has
  no palette; voxels will render black."

In `WorldFile::new`:
- Initialize `palette` to `[[0u8; 4]; 256]`.

### Step 4: Add palette GPU buffer

`src/tree64_renderer.rs` — add a function to create the palette storage buffer.

Add a new public function (not a method on `GpuTree64`, since the palette is
world-level, not per-tree):

```rust
/// Create a storage buffer holding the 256-color palette as vec4<f32>.
/// Each RGBA8 entry becomes [r/255, g/255, b/255, a/255].
pub fn create_palette_buffer(device: &wgpu::Device, palette: &[[u8; 4]; 256]) -> wgpu::Buffer {
    let float_palette: [[f32; 4]; 256] = std::array::from_fn(|i| {
        let [r, g, b, a] = palette[i];
        [r as f32 / 255.0, g as f32 / 255.0, b as f32 / 255.0, a as f32 / 255.0]
    });
    device.create_buffer_init(&wgpu::util::BufferInitDescriptor {
        label: Some("palette"),
        contents: bytemuck::cast_slice(&float_palette),
        usage: wgpu::BufferUsages::STORAGE | wgpu::BufferUsages::COPY_DST,
    })
}
```

Use `std::array::from_fn` (stable since Rust 1.63; this project uses edition
2024, which requires Rust ≥1.85).

### Step 6: Modify the slang shader

`assets/shaders/tree64_compute.slang` — three changes:

**a) Add palette binding after the leafData binding:**

```hlsl
[[vk::binding(5, 0)]]
StructuredBuffer<float4> palette;
```

**b) Initialize `hit.Normal` in `Tree64RayCast` to guarantee a zero normal on miss.**

`HitInfo hit;` in Slang does not zero-initialize fields (the compiled WGSL
happens to zero-init, but the Slang source shouldn't rely on that). After
the `hit.MaterialId = 0;` line inside `Tree64RayCast`, add:
```hlsl
  hit.Normal = float3(0, 0, 0);
```

**c) Fix hit detection — separate it from MaterialId:**

Currently the hit check is `if (hit.MaterialId != 0)`. Since palette index 0
is a valid color (the first palette slot), this false-negatives on voxels
using palette slot 0. (This is safe because `Tree64RayCast` only reads a
material ID when reaching a populated leaf cell — empty slots are excluded
by the occupancy mask — so MaterialId 0 in the hit path always means "voxel
with palette color 0," never "empty.")

The fix: check the normal instead — on a miss, `hit.Normal` stays
`float3(0,0,0)` (now guaranteed by the explicit initialization above). On a
hit, the normal is always non-zero (at least one axis of `sideMask` is true).

In the `main` function, replace:
```hlsl
  if (hit.MaterialId != 0) {
    // Material ID 1 = warm stone/brown
    float3 matColor = float3(0.6, 0.45, 0.3);
    color = float4(matColor, 1);

    float3 lightDir = normalize(float3(0.5, 1.0, 0.3));
    float ndotl = max(dot(hit.Normal, lightDir), 0.1);
    color = float4(matColor * ndotl, 1);
  }
```
with:
```hlsl
  if (any(hit.Normal != float3(0, 0, 0))) {
    float3 matColor = palette[hit.MaterialId].rgb;
    float3 lightDir = normalize(float3(0.5, 1.0, 0.3));
    float ndotl = max(dot(hit.Normal, lightDir), 0.1);
    color = float4(matColor * ndotl, 1);
  }
```

The `MaterialId` is the palette index stored in leaf data, which comes from
`v.i` (0-based, 0–254). The shader reads it via `ReadLeafMaterial` which
returns a `uint`. `StructuredBuffer<float4>` is indexable by `uint`.

**d) (No changes needed to `HitInfo` struct)** — only the initialization and
hit check changed; no new fields required.

## Maintenance notes

- **Shader drift**: If the slang source changes (e.g., new traversal
  optimizations), the compiled WGSL must be regenerated. The palette binding
  (binding 5), the hit detection change (`any(hit.Normal != 0)`), and the
  explicit `hit.Normal = float3(0,0,0)` initialization must be preserved
  across regenerations.
- **Slang variable names**: The compiled WGSL uses Slang-mangled variable
  names (`hit_1`, `MaterialId_0`, `Normal_0`, etc.). If the slang source
  changes, these names may shift — the manual WGSL edit in step 7b will need
  updating. Always rebuild with `slangc` when possible to avoid drift.
- **Future: per-material properties**: The `dot_vox::DotVoxData::materials`
  field contains PBR-like properties (`_rough`, `_metal`, `_spec`, etc.) that
  could be uploaded alongside the palette for more sophisticated shading — this
  plan deliberately defers that.
- **Future: missing palette in .vox**: If a .vox file provides no palette,
  `dot_vox` returns an empty vec. The bake step falls back to `DEFAULT_PALETTE`.
  If neither is available, the palette will be all zeros (black voxels). A future
